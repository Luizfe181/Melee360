FIO é uma adaptação para filesystem nativo do Xbox, não reprodução do protocolo MCC/EXI nem acesso a um PC remoto. Init valida seletores e cria/verifica game:\fio. Query verifica o diretório local disponível. Open usa CreateFileA e aceita apenas nomes simples nesse diretório; drives, separadores, controle e traversal são rejeitados. Até 32 handles, com gerações para rejeitar descriptors fechados/reutilizados. Escrita usa WriteFile, retorna contagem efetiva; fechamento libera handle; Exit fecha os handles vivos. Chamadas são serializadas pela seção crítica já usada no adaptador OS/PAD.

Contrato de flags deste adaptador: acesso 0 read, 1 write, 2 read/write; 0x200 create, 0x400 truncate, 0x800 exclusive. Combinações inválidas retornam erro. O export original hsd_3933 usa 0xA02. O transporte original apenas transmite flags ao host; sua implementação host não está no repositório, portanto este contrato local não é certificado como equivalência de todos os servidores FIO existentes. Erros de argumento são 0xB0, indisponibilidade/I/O 0x87, tabela cheia 0xA1. Não há APIs async, seek/read FIO, diretórios aninhados ou MCC implementados nesta etapa.

OSGetPhysicalMemSize consulta GlobalMemoryStatus.dwTotalPhys do Xbox. OSGetConsoleSimulatedMemSize relata a arena efetivamente reservada pelo port (8 MiB), com zero em falha de alocação; não relata 24 MiB fictícios do GameCube nem equivale ao heap HSD separado de 64 MiB. Prototypes foram adicionados ao header de compatibilidade. Inicialização completa HSD ainda precisa adaptar cálculos que assumem mapa de endereços GameCube; estas consultas não tornam HSD_OSInit original automaticamente compatível.
